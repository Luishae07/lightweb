What it is

Everything a small web needs

Light.web keeps the parts you actually use and leaves out the rest.

Names

A site is found by name, like search.cool. The name service (SFW) tells the browser where the site lives and which fingerprint to trust.

One page language

SFAGHC holds structure, layout, style, state and logic in a single .sf file. A page can fetch data and react to clicks.

Private by default

Every connection is encrypted and checked against the site's fingerprint. Tunnels only pass the traffic on.

Host from a folder

lwserve serves a folder, opens a free tunnel and registers your name. A home connection is enough.

Big downloads

One line, download_hosted_file=/thing.zip, offers a file of up to 7000 GB. It streams straight to disk.

Community name service

Anyone can run a read-only mirror of the name service. The browser picks the quickest one.

Get started

Three steps to your own site

The browser is a small Mac app for Apple Silicon and Intel. Hosting works on Linux, macOS and Windows.

1

Install the browser

One line puts Light.web.app in Applications. Open it, press Cmd+L and type sfadocs.nerd.

curl -fsSL https://raw.githubusercontent.com/Luishae07/lightweb/main/install-app.sh | sh
2

Write a page

Make a folder with a front page called index.sf:

page "Hello"
  document_description_crawl = "My first page"
  column gap=16
    h1 "Hello from my site"
    text "It works."
mysite.nerd

Hello from my site

It works.

3

Serve it

Install lwserve (Linux and macOS), then start it. -bore opens a free public tunnel and registers your name by itself:

curl -fsSL https://raw.githubusercontent.com/Luishae07/lightweb/main/install.sh | sh
lwserve -name mysite.nerd -bore -dir ./pages

Windows: download lwserve-windows-amd64.exe from the releases.

Language

SFAGHC in one look

Lines nest by indentation. {expressions} inside text are filled in, and the page redraws when a value changes.

page "Counter"
  state count = 0
  column gap=12 align=center
    h2 "Clicked {count} times"
    button "Add one" -> count += 1
    if count > 4
      text "That is plenty."

Also in the box

Components with slots, themes with dark mode, for loops, fetch and send to your own server, inputs and file downloads. The full guide is on the wiki, and as a site inside Light.web itself: open sfadocs.nerd.

How names work

The SFW in four steps

The SFW is the name service. It is like a phone book: it knows where a site lives and which fingerprint to trust. It never sees a single page.

A site registers its namelwserve sends the SFW the name (mysite.nerd), its address (for example a tunnel), its certificate fingerprint and its public key, all signed with the site's private key. It repeats this every 10 minutes, so a moved tunnel is found again.
The SFW checks and stores itThe ending (.nerd) must exist, the signature must be right and the clock must be within 10 minutes. A name is first come, first served: it belongs to whoever holds the key, so nobody else can take it over.
The browser looks the name upTyping mysite.nerd makes the browser ask the SFW LOOKUP mysite.nerd. The answer is the site's address and fingerprint (and its key, which also works as an address).
The browser connects and verifiesIt opens an encrypted connection to that address and accepts the site only if its certificate matches the fingerprint from the SFW. No certificate authority is involved, so a site can use a free self-made certificate.
Top-level namesA handful are built in. Anyone can make a new ending at maketld.web.
Signed recordsThe site's signature travels with the record, so a mirror cannot change an address unnoticed.
Only namesThe SFW holds names, addresses, keys and fingerprints. Pages go straight from the site to the browser.
Name service

Help keep names reachable

The browser asks the name service where a site lives. Anyone can run a read-only mirror, so lookups still work when the main one is away. A mirror cannot change where a name points: every record carries the site owner's signature and the browser checks it. The browser reads nodes.txt every five minutes and uses the quickest node.

Questions

Frequently asked

Is Light.web a replacement for the normal web?

No. It is a small web of its own, with its own names, its own page language and its own browser. It runs next to the normal web and does not use it.

Do I need a domain name or port forwarding to host a website?

No. Names like mysite.nerd come from the Light.web name service, and lwserve -bore opens a free public tunnel by itself, so a home connection is enough.

Is it safe to open a website?

Connections are encrypted and checked against the website's fingerprint, which the name service provides. A page can only talk to its own server: it cannot read your files or open other sites. Pages are text, so nothing runs on your computer.

Which systems does it run on?

The browser is for Mac, on Apple Silicon and Intel. lwserve, which hosts a website, runs on Linux, macOS and Windows. A phone version exists but is not released yet.

What does it cost?

Nothing. Light.web is free and released under the MIT license.

Who decides which names exist?

The name service gives a name to whoever registers it first, and a name stays with the holder of its key. Anyone can run a read-only mirror of the name service to help keep names reachable.

What is SFAGHC?

The page language of Light.web: one text file with structure, layout, style, state and logic, and no closing tags. The guide is on the wiki and at sfadocs.nerd.
